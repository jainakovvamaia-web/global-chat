# Запуск Global Community Chat

Пошаговая настройка: Supabase → ключи → Google → запуск сервера и сайта.

## 1. Проект Supabase

1. Зайдите на https://supabase.com → **New project**.
2. Регион — ближайший (например, Central EU / Frankfurt). Пароль базы сохраните себе.
3. Дождитесь, пока проект создастся (1–2 минуты).

## 2. Таблицы, функции и начальные данные

**SQL Editor → New query**. По очереди вставьте и выполните (**Run**) файлы из `chat-beck/supabase/migrations`:

1. `0001_schema.sql` — таблицы
2. `0002_functions.sql` — функции доступа, триггеры, Realtime
3. `0003_rls.sql` — защита (RLS)
4. `0004_seed.sql` — Бишкек: районы, 123 учебных заведения, чаты
5. `0005_groups_invitations.sql` — роли, закрытые группы, приглашения в группы

Порядок важен. Каждый файл можно запускать повторно — данные не задвоятся.
Если 0001–0004 уже выполнены, достаточно выполнить только `0005`.
Если когда-нибудь будете повторно запускать `0002`, после него снова выполните `0005`.

## 3. Ключи

**Project Settings → API Keys**. Понадобятся:

| Что | Где взять | Куда вписать |
|---|---|---|
| Project URL | Project Settings → Data API (`https://xxxx.supabase.co`) | `SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_URL` |
| anon / publishable key (публичный) | API Keys | `SUPABASE_ANON_KEY` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` |
| service_role / secret key (секретный) | API Keys | **только** `SUPABASE_SERVICE_ROLE_KEY` в `chat-beck/.env` |

> Секретный ключ даёт полный доступ к базе. Не отправляйте его в чат, не вставляйте во frontend
> и не загружайте в git. Его достаточно вписать в `chat-beck/.env` на своём компьютере.

### chat-beck/.env

Скопируйте `chat-beck/.env.example` в `chat-beck/.env` и заполните:

```
PORT=5000
SUPABASE_URL=https://xxxx.supabase.co
SUPABASE_ANON_KEY=<публичный ключ>
SUPABASE_SERVICE_ROLE_KEY=<секретный ключ>
FRONTEND_URL=http://localhost:3000
MEMBER_ID_SECRET=<случайная строка от 32 символов>
ANTHROPIC_API_KEY=<необязательно, для AI-помощника>
```

`MEMBER_ID_SECRET` можно получить командой:
`node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

### chat-front/.env.local

Скопируйте `chat-front/.env.local.example` в `chat-front/.env.local`:

```
NEXT_PUBLIC_API_URL=http://localhost:5000/api
NEXT_PUBLIC_SUPABASE_URL=https://xxxx.supabase.co
NEXT_PUBLIC_SUPABASE_ANON_KEY=<публичный ключ>
```

## 4. Настройки входа (Authentication)

**Authentication → URL Configuration**

- Site URL: `http://localhost:3000`
- Redirect URLs — добавьте обе:
  - `http://localhost:3000/auth/callback`
  - `http://localhost:3000/auth/reset-password`

**Authentication → Sign In / Providers → Email**

- Email — включён.
- **Secure password change** — включите. Тогда пароль нельзя сменить без недавнего входа,
  даже обращаясь к Supabase напрямую в обход нашего сервера.
- Confirm email — по желанию. Если включено, после регистрации придёт письмо со ссылкой.

## 5. Вход через Google

1. https://console.cloud.google.com → создайте проект (или выберите существующий).
2. **APIs & Services → OAuth consent screen** → тип *External*, заполните название и email.
3. **APIs & Services → Credentials → Create credentials → OAuth client ID**:
   - Application type: *Web application*
   - Authorized JavaScript origins: `http://localhost:3000`
   - Authorized redirect URIs: `https://xxxx.supabase.co/auth/v1/callback`
     (точный адрес показан в Supabase на странице провайдера Google)
4. Скопируйте **Client ID** и **Client Secret**.
5. Supabase → **Authentication → Sign In / Providers → Google** → включите и вставьте оба значения.

После входа через Google сайт попросит выбрать город и район — без них нет чатов по месту.

## 6. Сообщения в реальном времени (WebSocket)

Новые сообщения, правки, удаления, «печатает…» и сигналы уведомлений доставляет собственный
WebSocket-сервер Express — тот же сервер и порт, что и REST API, путь `/ws`
(`ws://localhost:5000/ws`). Supabase Realtime для этого не используется, ничего включать не нужно.

- Авторизация — тем же access token Supabase, что и для REST. Новых ключей и токенов нет.
- Сообщение отправляется через REST (`POST …/messages`), сохраняется в базе, и только после
  этого сервер рассылает событие тем, у кого есть доступ к чату.
- Адрес WebSocket сайт берёт из `NEXT_PUBLIC_API_URL` (http → ws, путь `/ws`).
  Если WebSocket будет на другом адресе, задайте в `chat-front/.env.local` переменную
  `NEXT_PUBLIC_WS_URL` (например, `wss://api.example.com/ws`).
- На хостинге прокси перед сервером должен пропускать WebSocket (заголовки Upgrade/Connection) на путь `/ws`.

## 7. Запуск

В двух окнах терминала:

```
cd chat-beck
npm install
npm run dev
```

```
cd chat-front
npm install
npm run dev
```

Откройте http://localhost:3000. Проверка сервера: http://localhost:5000/api/health → `{"data":{"status":"ok"}}`.

## 8. Стать администратором платформы

Роли две: `user` (все при регистрации) и `admin`. Через сайт или API роль получить нельзя —
только на сервере. Администратор может создавать группы и сообщества, приглашать в закрытые
группы и управлять ими.

1. Зарегистрируйтесь на сайте обычным способом.
2. В папке `chat-beck` выполните (нужен заполненный `.env`):

```
npm run set-role -- ваш@email admin
```

Снять права: `npm run set-role -- ваш@email user`.
Тот же результат даёт SQL в Supabase: `update public.profiles set role = 'admin' where email = 'ваш@email';`

## 9. Группы и приглашения

- **Создать группу** — кнопка «+» рядом с «Мои чаты» в боковой колонке (только у admin).
  Тип: общая, город, район, школа, университет или «Рядом». Доступ: открытая или закрытая.
- **Открытая группа** сама появляется у всех, кому подходит по профилю.
- **Закрытая группа** видна только участникам. Попасть в неё можно по коду приглашения.
- **Пригласить участников** — кнопка с человечком в шапке группы (у создателя и admin):
  срок действия (24 часа / 7 / 30 дней / бессрочно), лимит (1 — одноразовый, 10, 50, без лимита),
  список кодов с числом использований, «Копировать» и «Отключить».
- **Войти по коду** — кнопка с ключом рядом с «Мои чаты» или «Войти по коду» на странице сообществ.

## Как устроены автоматические чаты

- Общий чат `global-community` виден всем.
- Новый город, район или учебное заведение в справочнике сразу получает свой общий чат (триггеры в базе).
- Кто видит какой чат, решает база по городу, району и заведению из профиля.
  Сменили место в профиле — список «Мои чаты» обновился сам.
- Дополнительные чаты (новости района, потеряшки школы и т. п.) — это строки в таблице `chats`.

## 10. Деплой (GitHub → Vercel + Node-хостинг)

Кратко — в [README.md](README.md), раздел «Деплой»:

- Сайт (`chat-front`) — Vercel, Root Directory `chat-front`.
- Backend и WebSocket (`chat-beck`) — отдельный Node-хостинг (Render / Railway / Fly.io).
- На Vercel: `NEXT_PUBLIC_API_URL=https://<backend>/api`, `NEXT_PUBLIC_WS_URL=wss://<backend>/ws`,
  `NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`.
- На backend: те же переменные, что в `chat-beck/.env`, а `FRONTEND_URL` — адрес сайта на Vercel
  (можно несколько через запятую: `https://your-app.vercel.app,http://localhost:3000`).
- В Supabase (URL Configuration) и Google (JavaScript origins) добавить адрес Vercel к существующим.
